## [Unreleased] — станет 1.7.0

### Добавлено

- **Проверка обновлений**: при запуске (незаметно) и через меню приложения —
  «Проверить обновления» — программа сверяет версию с последним релизом на
  GitHub; при наличии новой версии — окно со ссылкой на страницу скачивания
  (открывается браузером). Ручная проверка сообщает и «у вас последняя
  версия», и ошибки сети.
- **Склейка выгрузок в один Excel**: кнопка «Склеить…» в «Архиве» объединяет
  показанные фильтром выгрузки одного отчёта (xlsx/csv) в один файл — лист
  «Данные» (шапка из самого старого файла + строки всех по хронологии;
  числа остаются числами) и лист «Файлы» (источники и совпадение колонок).
  Результат записывается в «Журнал» с кнопками действий.

### Исправлено

- **Различимые иконки после скачивания**: у кнопок «Открыть файл» и
  «Открыть папку» внизу «Загрузки» иконки были почти неотличимы (документ-
  и папка-со-стрелкой из Adwaita) — папка теперь с чистой иконкой папки
  (folder-symbolic), как в «Архиве».
- **Название отчёта «Продажи юрлицам (PDF)» → «Продажи юрлицам»**: суффикс
  формата был историческим (в августовском аудите сервер отдавал PDF);
  фактически формат файла определяет сервер — приложение сохраняет по
  реальному содержимому ответа (сейчас это xlsx), суффикс в названии вводил
  в заблуждение.

## [1.6.0] — 2026-08-18

### Добавлено

- **Кнопки действий в «Журнале»**: записи о скачивании получают 📂 «открыть
  файл», 📁 «открыть папку» и 🔗 «открыть в ЛК» (раздел отчёта в кабинете) —
  как в «Архиве». Контекст (первый файл + отчёт) сохраняется в БД (миграция
  v7) и пишется всеми исполнителями — GUI, CLI и расписания; ссылка ЛК
  резолвится при показе (в БД не хранится — ссылки меняются со временем).
  У старых записей (до v7) кнопок нет — контекста нет.
- **Кнопка «Открыть в ЛК» в «Архиве»**: в строке каждого скачанного
  Ozon-отчёта — переход к разделу личного кабинета (тот же нативный запуск
  браузера; у WB-отчётов ссылок нет — кнопка не показывается).
- **Кнопки «Открыть в ЛК»**: во вкладках «Отчёты» (иконка-ссылка у каждой
  строки) и «Загрузка» («Открыть в ЛК» у инфо-панели) — открывают раздел
  личного кабинета Ozon в браузере. Ссылки и 10 исправленных путей — из
  таблицы пользователя, сверенной по живому ЛК (у всех 21 отчётов).
- **Путь к файлу в журнале**: сообщения о скачивании теперь несут полные
  пути («Баланс» (июль 2026): скачано 1 файл(ов) — D:\…\balance.xlsx») —
  одинаково в GUI, CLI и фоновых запусках расписаний.
- **Копируемая справка**: весь текст «Справки» — единый текстовый блок:
  мышью выделяется любой фрагмент (в том числе через несколько разделов),
  Ctrl+A выделяет всё, Ctrl+C копирует; кнопка «Копировать всю справку»
  кладёт весь текст в буфер обмена одним нажатием.
- **Позаказный отчёт о реализации — Excel** (был CSV): конвертация в .xlsx
  с листом «Отчёт о реализации» (колонки и итоги как в кабинете Ozon —
  мэппинг сверен с живым ЛК-файлом, итоги совпали копейка в копейку)
  и листом «Детали (API)» со всеми исходными полями.
- **«О программе»**: автор, копирайт, лицензия (MIT/Apache-2.0), ссылка на
  исходный код, благодарности (Rust, GTK/libadwaita, vscode-icons, Inno
  Setup), оговорка о товарных знаках Ozon/WB.

### Исправлено

- **Колонки таблицы «Архива»**: ширина каждой ячейки теперь фиксирована
  (width_chars = max_width_chars + обрезка длинных) — прежде длинный текст
  раздвигал свою ячейку и колонки «разъезжались» построчно; иконка типа
  файла переехала из «Профиля» в «Формат» (с симметричным отступом в
  заголовке).
- **Размер окна**: окно не уменьшалось и открывалось раздутым (1325×919) —
  минимальную высоту задавали «Настройки» (~850px без скролла) и список
  «Отчётов» (21 строка без скролла), ширину — одна длинная строка фильтров
  Архива. Статичные вкладки («Настройки», «Расписания», «Отчёты») обёрнуты
  в скролл, фильтры «Архива» разложены на две строки — окно открывается
  1100×616 и свободно уменьшается.
- **Ссылки «Открыть в ЛК» в установленном приложении**: на части машин
  ссылки молча не открывались — gio не находил ассоциацию браузера в
  реестре Windows (на машине разработки ассоциация другая, поэтому там
  работало). Ссылка теперь открывается тем же нативным механизмом, что
  файлы и папки (`cmd start`, с явным квотированием — в ссылках есть
  символ `&`); если браузер всё же не запустился — диалог с причиной и
  кнопкой «Копировать ссылку».

### Изменено

- **Колонки таблицы «Архива» перетаскиваются мышью** (границы между
  колонками тянутся, таблица переведена на GtkColumnView): при расширении
  колонки обрезанный текст показывается целиком; колонка «Отчёт» — без
  фиксированной ширины (полные названия, когда окно достаточно широкое);
  полные значения — также в подсказках ячеек («Профиль» — имя, «Отчёт» —
  название + идентификатор). Выставленные ширины переживают обновление
  списка (фильтры/повторный запрос).
- **«Настройки» на подвкладках** (Файлы / Сеть / Расписания /
  Безопасность): вместо одной «простыни» полей высотой ~850px — компактные
  страницы по смыслу; подписи полей естественной ширины (пустоты посередине
  строки больше нет); «Сохранить» и статус — общие внизу.
- **Размер окна**: открывается ~1100×616 и свободно уменьшается до
  ~840×590 (прежде 1325×919 без возможности сжать): статичные вкладки и
  список «Отчётов» в скролле, длинные ряды фильтров/кнопок «Загрузки» и
  «Архива» разложены на два ряда; дефолт адаптивен к размеру монитора.
- **Таблица «Архива»**: сетка «рамками» — вертикальные линии между
  колонками + горизонтальные между строками; заголовки ровно над своими
  колонками (эластичная колонка «Отчёт» и в заголовке); кнопки действий
  компактной группой у правого края.

## [1.5.0] — 2026-08-15

### Добавлено

- `mdwf-gui --self-test <сценарий.json>` — event-level headless-драйвер
  GUI: прогон сценариев через тот же app-loop без окна/скриншотов, отчёт
  JSON с программными проверками (тестовая инфраструктура).
- **Экспорт списка «Архива»**: кнопка «Экспорт» сохраняет показанный (с
  учётом фильтров) список в Excel (.xlsx) или CSV для Excel («;», BOM);
  колонки как на экране + путь к каждому файлу.
- **Снапшот-страховка каталога**: при каждом открытии БД (до миграций)
  создаётся `<db>.bak` (`VACUUM INTO`), предыдущий ротируется в `.bak1` —
  страховка истории Архива/журнала на случай повреждения файла.
- **CI** (GitHub Actions): windows-latest + MSYS2/mingw64 — `cargo test
  --workspace` и `cargo clippy -D warnings` на каждый push/PR.
- Self-test сценарии `schedule_smoke` (добавление → ручной запуск →
  удаление расписания, источник журнала «запуск вручную») и `journal_clear`
  (очистка журнала); драйвер умеет `documents` для Browsable-отчётов.

### Изменено

- Колонка «Скачан» в «Архиве» показывает локальное время (было UTC).

## [1.4.0] — 2026-08-15

### Добавлено

- **Журнал событий в БД**: события (выгрузки, ошибки, расписания) пишутся в
  SQLite и переживают перезапуск; каждая запись помечена **источником** —
  «вручную (GUI)», «CLI», «расписание «X», автозапуск / запуск вручную /
  задача Windows / запуск из CLI»; сообщения несут человекочитаемое название
  отчёта и период («Баланс» (июль 2026)).
- **Вкладка «Архив»**: офлайн-навигация по всем скачанным файлам с фильтрами
  (профиль/отчёт/интервал дат), действия «открыть файл/папку», удаление
  записи+файла, персист фильтров между сеансами.
- **Пути отчётов в ЛК маркетплейсов** во всех поверхностях GUI («Отчёты»,
  «Загрузка», «Справка») — названия разделов сверены с живыми кабинетами
  продавцов (все 21 отчёт Ozon).
- **Интервал-виджет** (Неделя…Год + «Полугодие») с живым описанием периода;
  двойной клик по профилю/расписанию → редактирование; иконки типов файлов
  (vscode-icons), symbolic-иконки Adwaita.
- **Планировщик**: диалог «Когда…» вместо сырого cron, человекочитаемые
  карточки расписаний, фоновая задача Windows Task Scheduler, одиночный
  экземпляр (named mutex + AppMutex инсталлера).
- **Дистрибутив**: relocatable-бандл (~100 МБ, все DLL), Inno Setup
  per-user без UAC, брендовая иконка (exe + окно), GUI-subsystem без
  чёрной консоли, инсталлер одной командой `build-setup.cmd`.

### Изменено

- **Аудит Ozon API** (живой прогон): все 21 отчёт скачиваются по `--period`
  без ручных параметров — auto-fill SKU/складов/отправлений, поллинг
  async-отчётов, правильные форматы дат по каждому эндпоинту; JSON-отчёты
  конвертируются в Excel с русскими колонками; расширение файла — по
  реальному содержимому (magic bytes).
- **Аудит WB API** (сверка с OpenAPI-спекой): курсорная пагинация финансов
  (детализация перестала обрезаться на 1000 строк), обязательные параметры
  claims/удержаний, приёмка как async-флоу; отчёты конвертируются в Excel.
- Отчёт об отправлениях (postings): серверная генерация Ozon нестабильна →
  ретраи + фоллбэк-сборка xlsx из `/v3/posting/fbo/list` с пометкой в журнале.
- **Безопасность**: секреты профилей только в OS keyring (Windows Credential
  Manager); в SQLite — лишь несекретные поля.

### Исправлено

- CLI-исполнитель расписаний (`mdwf schedule run`, путь задачи Windows)
  терял скачанные файлы и не подставлял период из настроек расписания.
- Фильтр периода Архива для WB-документов (дата документа теперь
  протекает до БД; фильтр — пересечение интервалов дат).
- Circuit breaker не размыкал запросы; backoff rate-limiter терял штраф;
  cron расписаний считался в UTC вместо локального времени.
- «Чёрное окно» при запуске (консольная подсистема PE), пути в каталоге
  для CLI-выгрузок, pango-markup в справке.
